# SMS v2: statistics, journal, composer, automatic SMS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make /ops/sms tell the owner at a glance what the SMS account is doing (charts, costs, the debt warning's effect). Let them find any SMS fast (filters, export, a per-student history), send campaigns to any slice of the centre, and build their own automatic SMS.

**Architecture:**
- Everything stays inside `backend/sms` and `frontend/src/features/ops/sms`, plus a student tab on the person page.
- Every paid send still goes through `delivery.deliver()`, the claim-first unique row.
- Automatic SMS use approach **A, "watch the tables"**:
  - a beat task asks each enabled automation's source table every minute what is new;
  - no other app gets a hook;
  - a missed minute, a deploy or quiet hours lose nothing, because the dedupe key makes a repeat a no-op.

**Tech Stack:**
- Backend: Django + DRF `APIView`s, Celery beat, Postgres. Tests run on SQLite with the no-migrations settings.
- Frontend: Next.js, React Query, recharts (through `@/components/ui/charts`, lazy-loaded), Tailwind, vitest.

**Spec:** none, by the owner's rule ("spec=code"). The design was approved section by section in chat on 2026-11-01 and is restated in "Approved design" below. Earlier plans this builds on:
- `2026-10-18-eskiz-sms-debt-warnings.md`

- `2026-10-18-sms-ops-panel-api.md`, the binding JSON contract.

## Approved design (chat, 2026-11-01)

**1. Automatic SMS builder.**
- The owner creates automations. Each has a name, a trigger, an audience, an approved template with one value per slot, optional quiet hours, a daily limit, and an on/off switch.
- Triggers:
  - **month days**: chosen days of the month at an hour;
  - **absent**: unexcused ABSENT, once the register closes, which is 2 h after the lesson ends;
  - **payment**: a new lc-up payment;
  - **joined**: a student added to a class.
- Audience: all centre students, chosen groups, a subject/level/branch filter, or debtors with a minimum debt (debtors is month days only).
- Slot values: name, group, payment amount, debt, date, or typed text. A live SMS sample shows the result.
- Quiet hours are set per automation. Events inside them wait and go when the quiet hours end.
- Safety:
  - only events after the moment the automation was switched on count;
  - a 7-day "who would have got it" preview comes before switching on;
  - events older than 48 h are never sent;
  - one SMS per event per student;
  - forbidden-word scrub, and one retry of an operator rejection;
  - stop on a low balance, with a panel alert;
  - a reminder to switch the same SMS off in lc-up.
- The debt warning stays as it is, shown at the top of the Automations tab as a "system automation". The Debt warnings tab folds into Automations. The journal names the automation.

**2. Statistics & charts.**
- Four count-up tiles: balance (≈ how many SMS it covers), today (sent / left), this month's delivery %, this month's cost.
- A red balance banner on every SMS tab when the balance does not cover the next 24 h: debt run + scheduled campaigns + automations' average daily cost.
- Range: 7 / 30 / 90 days, this month, or custom.
- Charts:
  - delivery by day: stacked delivered / undelivered / rejected, with a delivery-% line;
  - delivery % by operator (Beeline, Ucell, Uzmobile, Mobiuz, Perfectum, Humans), from the phone prefix;
  - cost by month split by kind, plus cost by day. Estimated at 170 so'm a part; from now on each SMS stores its own unit price;
  - debt warning effect per month: warned → paid within 1 / 3 / 5 days → not paid (frozen on day 6).
- Undelivered list with plain-word reasons, operator and attempts. Resend works per row or for a selection, always behind a count + price confirm. Only UNDELIVERED / REJECTED / FAILED can be resent; a delivered SMS never is.
- Animations: count-up, charts draw in, skeletons, smooth tab change. All off under reduced motion.

**3. Journal.**
- Filters with counts: date range (from–to plus today / 7 / 30), status, kind, operator, group, teacher, template, campaign, automation. Active filters show as chips, with "clear all", and live in the URL. Group and teacher mean the student's *current* class.
- Rows are grouped by day under sticky headers: name + group, phone + operator, source, status in plain words, one line of text.
- The row drawer shows the full text, a timeline (created → sent to eskiz → delivered / undelivered), the reason, eskiz's request id, and Resend.
- Clicking a name opens that student's SMS history.
- Export: the filtered list, all pages, as CSV with a UTF-8 BOM, so Excel opens it with Uzbek letters intact.
- A new SMS tab on the /ops student page: a timeline, plus "Send SMS".

**4. Campaigns.**
- One page replaces the wizard. Cards ① Who → ② Message → ③ When on the left fold into one-line summaries when done. On the right: a phone-style preview plus "142 students · 3 no phone · 2 parts · ~48 280 so'm · balance OK", and a final confirm.
- ① Who: one student, groups (many, with search and select-all), a filter (subject, level, branch, lesson days; several values each), or debtors. The count updates live. "See the list" opens a list where people can be removed. A student in two groups gets one SMS.
- ② Message: template cards with a **name (alias)**, the most used on top, and search.
- ③ When: now, or at a time ("Today 10:00", "Tomorrow 10:00"). A past time is impossible; 21:00–09:00 warns.
- The campaigns list shows a delivery ring per campaign. The campaign page adds an operator chart, its undelivered list and Resend, plus **Repeat** (a new campaign prefilled from this one).
- Templates tab: alias editing (sync never overwrites it) and "used N times / last used".

**5. Look & delivery.**
- Tabs: Overview · Journal · Campaigns · Automations · Templates, with small counters.
- The /ops shell is unchanged.
- One SMS accent colour. Fixed status colours: green delivered, amber undelivered, red rejected, grey pending. Fixed operator colours.
- No decorative bars: every visual carries information.
- A live dot on a sending campaign (refresh every 5 s), and toasts after actions.
- Mobile: tables become cards. The composer preview moves below, with a sticky Send bar.
- Delivery: three PRs, each a zero-downtime deploy with additive migrations only. Automations ship switched off.

## Global Constraints

- Every SMS mutation hook in the frontend spreads `MUTATION_DEFAULTS` (`retry: false`). The global QueryClient retries mutations, and a retried send is paid twice.
- Every paid send goes through `delivery.deliver()`.
  - PENDING, SENT, UNCERTAIN and DELIVERED rows are never sent again.
  - A hand resend may pick up only `RESENDABLE = (UNDELIVERED, REJECTED, FAILED)`.
- Every send button in the UI confirms first with the SMS count and the estimated price.
- Every new endpoint is a plain `APIView` subclass of `_AdminView` (`IsGlobalAdmin`). Never `.as_view({...})`.
- The phone is always lc-up's: `normalize_phone(LcupStudentLink.phone)`. A recipient without a link or phone is skipped and listed, never guessed.
- `switchboard.env_enabled()` (`SMS_DEBT_WARNINGS_ENABLED`) is the master kill switch for automations too.
- Migrations add tables and nullable or defaulted columns only. Run every new migration on local Postgres before the PR (memory: postgres-like-index-double-create).
- Panel copy is English, like the rest of /ops. Failure reasons are plain words ("Operator rejected"), never raw eskiz codes alone.
- Animations sit behind `prefers-reduced-motion: reduce`. No bar or meter that only restates a number already shown.
- Days, hours and "today" are Asia/Tashkent: `timezone.localtime`, Celery's timezone.
- List endpoints use `users.changelist` (`apply_search`, `facets`, `paginate`). A facet's choices are ONE grouped query, never a COUNT per option.
- CSV goes out through `core.csv_download.csv_download_response`. No new Python or npm dependency anywhere in this plan.
- Every new or changed field goes into `docs/superpowers/plans/2026-10-18-sms-ops-panel-api.md` in the same task that adds it.
- Backend tests: from `backend/`, run `SECRET_KEY=test-secret DEBUG=True LMS_FORCE_SQLITE_FOR_TESTS=1 /Users/macbook/.pyenv/versions/3.12.2/bin/python3 manage.py test sms --settings=config.settings_test_nomigrations -v 1`. Only a literal `OK` line counts as green.
- Frontend tests: from `frontend/`, run `npx vitest run src/features/ops/sms src/features/ops/changelist src/features/ops/people` and `npx tsc --noEmit -p .`.
- Commits are authored by `Viltrumlik <viltrumlik@gmail.com>`. One branch and one PR per part, each PR targeting `main`.

```json
{"from": "2026-10-03", "to": "2026-11-01",
 "totals": {"sent": 0, "delivered": 0, "undelivered": 0, "rejected": 0, "failed": 0, "pending": 0, "rate": null, "cost": 0},

 "debt_effect": [{"month": "2026-11", "warned": 194, "paid_1": 40, "paid_3": 88, "paid_5": 120, "unpaid": 74}]}
```

Rules the tests pin:
- `rate = delivered / (delivered + undelivered + rejected)`, or null when that sum is 0. SENT, PENDING and UNCERTAIN are unfinished and left out.
- `cost = Coalesce(parts, 1) × Coalesce(unit_price, price_per_part())`. Rows with a status of FAILED cost 0.
- Days come from `created_at` in Tashkent (`TruncDate(..., tzinfo=Tashkent)`). The range is inclusive.
- With no params, the range is the last 30 days ending today. A range over 366 days, `to < from`, or an unparsable date is a 400 with code `range`.
- `by_operator` lists every one of `NAMES` plus `"Other"` that has at least one row, in `NAMES` order with `"Other"` last.
- `debt_effect`:
  - `warned` counts distinct `lcup_student_id` with an accepted `debt_warning` in the month;
  - `first` is that student's earliest `run_on`;
  - `paid_d` counts warned students with an `LcupPayment(kind="payment")` whose `paid_on` lies between `first` and `first + (d - 1)` days, inclusive;
  - `unpaid = warned - paid_5`;
  - refunds and extras are ignored.

- Test: `backend/sms/tests_automation_run.py`, `backend/sms/tests_debt_warnings.py` (still green)

**Interfaces:**
- Produces:
  - `balance.cached() -> int | None` (cache only, no eskiz call) and `balance.fetch() -> int | None` (today's `_balance` behaviour; the views call it)
  - `automations.in_quiet_hours(a, local_dt) -> bool`. It handles a window across midnight; `start <= t < end`.
  - `automations.run(client, a, now) -> dict` returning `{"sent", "skipped", "quiet": bool, "paused": str}`
  - `delivery.retry_operator_rejections(qs, now) -> int`, the generalised body of `give_operator_rejections_one_more_try`, which now calls it
  - `tasks.run_automations()`, beat entry `"sms-run-automations": crontab(minute="*")`, with a per-automation lock `sms:automation-lock:<id>` (cache.add, 600 s)
  - `forecast.need_next_24h()["automations"]` = the 7-day average daily `cost_expr` of `kind=automation`

`run`, in order:
1. If the env switch is off, or the automation is not enabled, return.
2. If in quiet hours, return `quiet`.
3. Retry operator rejections for this automation's messages sent 30 min to 24 h ago.
4. Compute `left = daily_limit` minus today's rows of this automation that are not FAILED.
5. Collect `events`, oldest first, and keep those without a non-FAILED row for their key.
6. If `balance.cached()` is not None and is below the cost of the first `left` events, set `paused_reason = "balance"`, save, and return.
7. For each event, up to `left`:
   - `render_event`;
   - `forbidden.scrub`;
   - skip the same (phone, text) twice in one run;
   - `deliver(kind=automation, run_on=event.run_on, dedupe_key=event.key, automation=a, template_eskiz_id=a.template_eskiz_id, user, lcup_student_id)`.
8. Stop after `campaigns.BREAKER_AFTER` FAILED or UNCERTAIN in a row.
9. Clear `paused_reason` after a run that sent.
